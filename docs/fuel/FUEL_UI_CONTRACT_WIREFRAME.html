TruckERP Fuel — Post-Process UI Contract

Authoritative visual contract for Fuel home / Recent Activity after Process. Pairs with docs/fuel/FUEL_PROVIDER_WALL_ARCHITECTURE_DELTA.md (provider wall, canonical read model). Checkpoint 0 — wireframe only; implementation must conform.

Locked concepts

  1. Main Fuel expanded row = ONE TruckERP operational workspace (no second table, no inline parser block).
  2. Operational workspace uses canonical / final TruckERP fields only (fuel_transactions, batch summary DTOs).
  3. Same operational layout for BVD, Nationwide, WEX, and future providers.
  4. Provider-native / parser values are NOT rendered inline on the main Fuel page expand row.
  5. "Open source" opens a separate provider-native evidence overlay or view.
  6. Close on that overlay returns to the main Fuel workspace (expand row or list context unchanged).
  7. BVD is the visual / design baseline only — BVD source data types and components are NOT the shared TruckERP data contract.
  8. Never adapt Nationwide, WEX, etc. into FuelBvdRow (or BVD tables) just to reuse BVD components.
